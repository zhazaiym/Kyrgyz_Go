## Остаточный риск

Лимиты IP и пары «аккаунт + IP» устраняют блокировку владельца с другого адреса и ограничивают обычный перебор. Они не являются вторым фактором и не останавливают распределённую атаку с большим числом адресов. Для строгой защиты входа админов нужен MFA; для клиентского входа — CAPTCHA или проверка владения email после порога. Глобальная жёсткая блокировка аккаунта намеренно не используется, потому что её можно превратить в отказ в обслуживании для владельца.

Очередь переводов остаётся in-memory. Незавершённые задания восстанавливаются сканированием при старте; перевод, который провайдер не смог сделать, безопасно остаётся на исходном языке. Это не гарантирует доставку без успешного последующего вызова провайдера.
