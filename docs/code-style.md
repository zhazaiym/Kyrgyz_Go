# Стиль кода

Ориентир — оформление моделей, сериализаторов и методов обработчиков из
[BookingSiteii26](https://github.com/mazitovomar64-ux/BookingSiteii26),
коммит `163f0fdeca4c4564f7621cd0fa3464b1a892199d`.
Ранее указанный `store_fastapi_26` больше не используется как образец.
Единые правила проекта закреплены в `pyproject.toml` и `.editorconfig`.

- Четыре пробела на уровень вложенности, без табуляции.
- Одинарные кавычки; тройные двойные кавычки для docstring.
- Импорты тремя группами: стандартная библиотека, сторонние пакеты, наш код.
  Между группами — пустая строка, внутри — сортировка.
- Короткие импорты записываются одной строкой. Длинные списки имён помещаются
  в скобки и переносятся компактными группами, а не по одному имени на строку.
- Две пустые строки между функциями и классами верхнего уровня.
- Длинные аргументы и цепочки запросов переносятся на отдельные строки.
  Ориентир длины строки — 100 символов; длинные строки текста не разрываются
  искусственно, если это ухудшает чтение.
- В функциях последовательные действия читаются сверху вниз: получить данные,
  проверить условия, выполнить операцию, вернуть результат. Пустые строки
  отделяют смысловые шаги; не нужно отделять каждую строку.

В образце некоторые отступы и интервалы отличаются между файлами. Здесь
сохранён единый вариант: без лишних уровней вложенности, случайных пробелов
и неодинаковых отступов продолжения строки. Ширина 100 — правило нашего
проекта для более компактных объявлений; это не настройка из образца.
Импорты остаются явными и сгруппированными. Классы Django/DRF не переносятся:
оформление применяется к существующим моделям SQLAlchemy, схемам Pydantic
и обработчикам FastAPI. Изменения архитектуры и API не входят в эту правку.

Привести оформление к правилам:

```powershell
.venv/Scripts/python.exe -m pip install -r requirements-dev.txt
.venv/Scripts/python.exe -m scripts.format_code
```

Проверить перед отправкой изменений:

```powershell
.venv/Scripts/python.exe -m ruff check .
.venv/Scripts/python.exe -m scripts.format_code --check
.venv/Scripts/python.exe -m pytest -q
```

CI проверяет и импорты, и форматирование. Миграции Alembic, тесты и код ИИ
оформляются по тем же правилам. Для сравнения с веткой автора ИИ теперь
следует учитывать форматирование: буквальное совпадение файлов больше не
ожидается. Изменений логики агента в этой правке нет.

Команда `scripts.format_code` сначала применяет Ruff к оформлению тела файла,
затем isort к импортам с компактным переносом. Обычный `ruff format .`
может снова развернуть длинные импорты в столбик; для проекта используется
единая команда выше. Версии инструментов закреплены в `requirements-dev.txt`.

При переходе к стилю сравнивалась AST-структура 117 Python-файлов и наборы
импортируемых имён. Единственное отличие вне порядка импортов — удалённый
пробел в конце строки `Revises:` внутри docstring начальной миграции;
исполняемые выражения сохранены. Проверка Ruff охватывает 118 файлов:
117 Python-файлов и `pyproject.toml`.

`ruff check`, `ruff format --check` и `git diff --check` прошли.
