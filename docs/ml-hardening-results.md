# ML, Gemini, API и бронирование: доработка 29 октября 2026

Работа выполнена по [согласованному проекту](superpowers/specs/2026-10-29-ml-hardening-design.md). База сравнения — `489b0a9` и существующие локальные изменения. Сервер не обновлялся, рабочая БД не мигрировалась, платные вызовы Gemini не выполнялись.

## Структура и промпты

- Реализация перенесена в [ML](../ML/README.md): агент, промпты, схемы извлечения, контекст, read-only tools, конфигурация, ленивые клиенты Gemini, ошибки и вызов переводов. В `mysite/chain` и старом модуле переводчика оставлены совместимые импорты тех же объектов модулей.
- Подтверждение и отказ от заявки перенесены в `mysite/api/booking_intent.py`. Создание заявки, права и хранение остаются в backend. Модель не получает инструментов записи.
- Промпты относительно HEAD сокращены с 59 438 до **5734** символов для SYSTEM и с 21 875 до **3841** для EXTRACT. Существовавший локальный вариант 5980/3919 сохранён по смыслу и дополнительно сокращён; извлечение явно названного ID вне ограниченного списка допускается только с серверной проверкой активности.
- До пяти раундов модели, восьми tool calls суммарно, 15 секунд на инструмент, 16 000 символов на его результат, общий deadline 150 секунд с настройкой `CHAT_RESPONSE_TIMEOUT`. Неполнота выдачи обозначается ошибкой, а не выдуманным отсутствием услуг.
- Dockerfile, CI и упаковка релиза включают `ML`. В CI добавлен отдельный запуск ML unit-тестов без PostgreSQL.

## Исправленные ошибки

1. Классификация Gemini по тексту заменена проверкой статусов и ограниченным обходом причин исключений. 429, 503, 504 и 403 покрыты проверками реального HTTP-слоя SDK через MockTransport. Текст провайдера не возвращается пользователю. Логи приложения не сохраняют содержимое исключений с клиентскими данными/ключами.
2. Ответы с блокировкой провайдера, некорректными tool calls и незавершённым выходом не публикуются как успешные. Один компактный повтор при исчерпании бюджета остаётся в общем deadline.
3. Переводчик понимает текстовые блоки Gemini, а не преобразует список блоков в Python-строку. Заблокированный или обрезанный перевод не записывается как успешный.
4. Отключение WS во время генерации отменяет обработку и освобождает lock/AI capacity. Во время обработки сохраняется ограниченная очередь последующих кадров.
5. Очистка сбойной реплики использует точную связь ответа с исходным сообщением. Ответ другого worker больше не сохраняет неудачную реплику в истории.
6. Одинаковые конкурентные сообщения получают отдельные строки. Проигравший запрос удаляет только собственную реплику, сохраняя пару победившего запроса.
7. Отмена во время DB-подготовки дожидается worker и очищает конкретную незавершённую реплику. Уже зафиксированное подтверждение/отказ не откатывается.
8. Туры вне первых 256 ID проверяются точным запросом при выборе. Ограничение контекста больше не является отказом в выборе существующего активного тура.
9. Демонстрационные префиксы со смешанным регистром (`TeSt:`, `ТеСт:`) также исключаются из AI-каталога до ограничения выдачи; проверка не зависит от locale PostgreSQL.

Все три дополнительных замечания независимого ревью воспроизведены тестами до исправления. Повторное ревью не выявило оставшихся важных замечаний в проверенных изменениях; reviewer не запускал тесты самостоятельно.

## PostgreSQL и права

Добавлена миграция `20261029_0017`: nullable self-FK `chat_messages.reply_to_message_id`, уникальность связи и `ON DELETE SET NULL`. Существующие сообщения сохраняются без backfill; изменения названий таблиц или удаления истории нет. Проверяются upgrade из 0016 с сохранением данных, downgrade с сохранением истории, свежий upgrade head и `alembic check`.

Тесты используют отдельные `test_kyrgyzgo_*` базы на локальном PostgreSQL 17. Для тестового соединения использован `127.0.0.1`, потому что адрес Docker-хоста из локального `.env` недоступен вне контейнера. `.env` не переписывался.

OpenAPI содержит прежние **137 операций и 91 схему**. Матрица прав отправляет запросы на все **62 операции изменения каталога** от гостя и клиента; каждая требует администратора. Существующие тесты проверяют владельца сессии/подборки, отзыв токенов, IP-доступ администратора, состояния заявки, revision и конкурентное подтверждение.

## Безопасность зависимостей и окружение

В проектную `.venv` установлены зависимости из `requirements-dev.txt`. Первичный локальный аудит выявил старые неиспользуемые `python-jose==3.5.0` и `ecdsa==0.19.2`; ни код, ни runtime requirements их не используют. Они удалены из этой `.venv`. Повторные `pip_audit --local` и `pip check` не выявили известных уязвимостей и нарушенных зависимостей. Отдельный аудит полного графа `requirements.txt` также завершился сообщением `No known vulnerabilities found`. Это результат базы advisories на момент запуска, не гарантия отсутствия всех уязвимостей.

Postman CLI не запустился из-за недоступного управляемого Private Cloud manifest. Ограничение политики не обходилось. Ошибки HTTP-зависимости проверены установленным SDK с `httpx.MockTransport`; запросы не уходили в Gemini. Docker Engine не запущен: образ не собирался, работа production не проверялась. Тесты рендеринга Compose, которым нужен только CLI, входят в общий suite.

## Локальные файлы и развёртывание

Перед production-релизом требуется отдельно обновить доверенный серверный deploy-скрипт для допуска каталога `ML` и применить миграцию по процедуре резервного копирования. Это описано в [ручном развёртывании](manual-deployment.md). Простая загрузка файлов не подтверждает установку новой версии.

Один общий запуск форматтера дополнительно изменил оформление локальных копий `.chat-deploy` и неиспользуемого `mysite/chain/catalog.py`; функциональная правка в них не выполнялась. Исторические копии `.chat-deploy` теперь исключены из lint/format и не входят в runtime-архив. Существующие локальные промпты, планы и содержательные изменения сохранены.
