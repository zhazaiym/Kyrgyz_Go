# План проверки и улучшения ИИ-консультанта

Этот документ превращает замечания по LangChain/Gemini в проверяемый план для автора ИИ-части. Он не заменяет реализацию агента и не предлагает переписывать его промпты без оценки качества.

Связанные материалы: [итог второго ревью](second-review.md), [код агента](../mysite/chain/agent.py), [инструменты каталога](../mysite/chain/tools.py), [промпты](../mysite/chain/prompts.py).

## Текущее состояние по коду

- Агент использует LangChain tool calling с Gemini. Ему доступны только инструменты чтения; создание и подтверждение брони остаются в backend.
- На сообщение отводится максимум пять раундов вызова инструментов. Цикл заканчивается раньше, если модель возвращает обычный ответ.
- Изменения данных клиента извлекаются отдельным вызовом с `EXTRACT_PROMPT`; это дополнительная стоимость и отдельная точка возможной ошибки.
- Максимумы выходных токенов задаются `CHAT_MAX_OUTPUT_TOKENS` (по умолчанию 1536, верхняя граница 4096) и `CHAT_EXTRACT_MAX_OUTPUT_TOKENS` (512, верхняя граница 1024). Число повторов Gemini по умолчанию равно одному.
- В ревью длина `SYSTEM_PROMPT` составляла 1143 строки / 59 438 символов, `EXTRACT_PROMPT` — 471 строку / 21 875 символов. Это размер текста, а не число токенов.
- Документация Gemini указывает на implicit caching для моделей 2.5 и новее. Реальные cache hits, токены и денежная стоимость этого приложения не измерялись; наличие кэширования нельзя считать подтверждённым для конкретных вызовов.
- Прежняя проверка обнаружила ответ с услугой, которой нет в каталоге. Этот случай не считается исправленным, пока не пройдёт набор проверок ниже.

## 1. Сначала добавить измеримость

Добавить безопасную телеметрию на каждый вызов модели, не записывая API-ключи, полный промпт, персональные данные и полный текст чата:

- анонимный ID сценария/запроса и номер шага: агент или извлекатель;
- имя модели, причина завершения, число раундов и вызовов инструментов;
- usage из ответа провайдера: входные, выходные и прочие доступные токены;
- usage cache read/write, если провайдер возвращает эти поля;
- задержка каждого вызова, повторы, таймауты, ошибки и исчерпание лимита;
- ответ инструмента в безопасном агрегированном виде: имя, число результатов, ID каталога, который можно сопоставить в тесте.

Отсутствующее поле usage/cache записывать как `unknown`, а не как ноль. Не сохранять пользовательский ввод в обычные логи. Для диагностики использовать синтетические или обезличенные сценарии.

## 2. Зафиксировать базовый набор диалогов

До изменения промптов сохранить версию кода, модели и конфигурации, прогнать набор не менее трёх раз и записать медиану и худший результат. В набор включить:

1. Вопросы о стране, правилах поездки и компании, где вызов инструмента не нужен.
2. Поиск тура, отеля и транспорта по точным и неполным критериям.
3. Пустую выдачу, деактивированную услугу и услугу с `ТЕСТ:`/`TEST:` в названии.
4. Несколько похожих позиций каталога и просьбу сравнить их.
5. Несколько языков, опечатки, неполные ответы и исправление ранее введённых предпочтений.
6. Попытки пользователя заставить агента придумать цену/наличие, показать скрытый объект или выполнить запись/бронь.
7. Prompt injection в сообщении пользователя и в описании каталожной записи: игнорировать инструкции внутри данных и не выдавать их за системные команды.
8. Ошибку/пустой ответ инструмента, таймаут модели и исчерпание лимита раундов.

Для каждого сценария записать допустимые факты каталога и ожидаемый следующий шаг. Секреты и реальные персональные данные в фикстуры не включать.

## 3. Проверить утверждения о каталоге (B14 и найденная галлюцинация)

Оценивать фактические утверждения отдельно от стиля ответа:

- Каждое упомянутое название, цена, дата, вместимость и доступность должны быть подтверждены текущим ответом инструмента или явно предоставленным контекстом.
- При отсутствии результата агент должен сообщить, что подходящего предложения не найдено, и предложить уточнить критерии; запрещено заполнять пробел правдоподобной выдумкой.
- Неактивные и демонстрационные позиции не должны предлагаться, даже если пользователь просит их найти.
- Ответ должен сохранять различие между «неизвестно», «не найдено» и подтверждённым фактом.
- Для каждого провала сохранять минимальный сценарий, результат инструмента и ответ модели в закрытом тестовом артефакте; не включать секреты/PII в репозиторий.

Критерий выпуска: ноль неподтверждённых фактов о каталоге и ноль выдуманных услуг на фиксированном регрессионном наборе; любые случайные/недетерминированные провалы повторно прогонять и разбирать, а не усреднять.

## 4. Измерить стоимость, затем менять бюджет и подсказки

Для каждого сценария рассчитать стоимость по фактическому usage и актуальным тарифам выбранной модели: отдельно обычный вход, cache read/write и выход; добавить извлекатель и все повторные вызовы. Сводить медиану и p95 на диалог, число вызовов и долю ошибок. Цены брать из актуальной официальной документации Gemini на момент измерения, а не зашивать в тест.

Затем сделать отдельную экспериментальную ветку и менять по одному фактору за раз: повторяющиеся инструкции, объём истории, число раундов, размер выходного бюджета, необходимость отдельного извлечения. Каждый вариант сравнивать с базовым набором по стоимости, p95 задержки, точности каталога, корректности извлечения полей и успешности пользовательского сценария.

Не включать сокращение промптов/бюджета, если оно ухудшает любой критичный сценарий. Кэш считать работающим только после наблюдения соответствующих usage полей на реальных вызовах; кэш не считать гарантированной экономией.

## Критерии готовности

- Есть автоматизируемый набор сценариев и записанный baseline.
- Usage/cache/latency можно сопоставить с шагом агента без записи секретов и полного пользовательского содержимого.
- Каталожные ответы проходят проверку подтверждённых фактов; пустая выдача не приводит к выдумке.
- Сбои модели и инструментов обрабатываются контролируемо, а число вызовов остаётся в заданной верхней границе.
- Изменение промпта или бюджета сопровождается сравнением до/после по качеству и стоимости.
- До выполнения этих критериев B14 и проблема галлюцинаций остаются открытыми.
