Автоматическое восстановление dump поверх живой БД не добавлялось: это могло
бы потерять новые заявки. Вместо предположения о совместимости произвольной
миграции deploy останавливается до активации схемно несовместимого кандидата.
Тесты управления деплоем используют подменённый Docker, а не боевой сервер.

Переводы остаются best effort: сбой или перегрузка может оставить исходный
текст. Старый перевод при смене оригинала очищается; проверка снимка исходных
полей предотвращает позднюю перезапись новой правки. Возможное завершение
процесса между commit и переводом не откатывает сохранённый каталог.

Миграция `20261028_0013` добавляет статусный триггер и индексы expiry.
Для production нужен Alembic: create_all сам по себе не создаёт этот триггер.

## Уточнения и сохранённая совместимость

- A3: worker-local HTTP-квота уже была документирована. При рестарте или LRU
  вытеснении coarse-счётчик теряется; это не финансовый лимит. Критичные
  лимиты остаются в PostgreSQL, сетевой DDoS требует внешней защиты.
- B15: /auth и /account сохранены ради совместимости разных форм регистрации;
  учётная запись и вход общие, нормализация email использует один валидатор.
- B18: старый административный API сохранён, добавлены limit/offset и единый
  порядок вместо недоступности записей за первыми ста элементами.
- B16: digest и часы ORM вынесены в общие утилиты. Объекты BoundedPasswords
  используют один класс и общий лимит вычислений; отдельные экземпляры не
  являются копиями реализации.
- B17: translate_text удалён, translate_tour использует translate_fields.
  Разные схемы хранения переводов не мигрировались.
- A8: defaults/bounds находятся в одном RESOURCE_LIMITS; значения и валидатор
  кэшируются. Повторный вызов middleware не перечитывает настройки.
- A11: invalid_preview и сообщение удаления услуги находятся в общем TEXT.
- A14: статусный helper импортируется на уровне модуля.
- A9/B19: проверка отсутствующего request нужна для несуществующего ID.
  Проверка двух подборок оставлена для старой/повреждённой схемы; в корректной
  новой схеме дубли запрещены UNIQUE.
- A13: status:null воспроизводимо получает 422 от Pydantic до обработчика,
  включая completed. Заявленное поведение с 409 не подтвердилось.
- B6 не менялся: хук SQLAdmin корректен. Закомментированные классы админки
  уже удалены в 360424b; повторного блока нет.

## ИИ и остающиеся действия

SYSTEM_PROMPT: 1143 строки/59438 символов; EXTRACT_PROMPT: 471/21875.
Пять раундов — верхняя граница; обычный ответ заканчивает цикл раньше.
Отсутствие явной настройки не доказывает отсутствие cache:
[Gemini включает implicit caching для моделей 2.5 и новее](https://ai.google.dev/gemini-api/docs/caching).
Cache hits и реальная стоимость в этом проходе не измерялись.

**B14 остаётся задачей оптимизации с автором ИИ:** измерить usage/cache и
качество на фиксированных диалогах, затем сокращать политику или менять
budget/caching. Без сравнений большие подсказки не переписывались.
Галлюцинация услуг из прежнего аудита также не объявляется исправленной.

Перед production нужны отдельные действия:

- CI/CD отключён вручную; здесь он не включается.
- Обновить установленный `/usr/local/lib/kyrgyzgo/ci_deploy.py`: новая копия
  в Git сама не заменяет старый SSH-gateway на сервере.
- Применить Compose-сеть с сохранением production PostgreSQL и override.
  Согласовать PROXY_SUBNET, CADDY_PROXY_IP, API_PROXY_IP, FORWARDED_ALLOW_IPS.
- Выполнить отдельную безопасную миграцию перед автоматическим deploy при
  несовпадении голов схемы. Не подменять этот шаг безусловным stamp.
- Смена раскрытых паролей, отзыв боевых токенов и удаление истории остальных
  веток остаются операционными действиями. Пользовательские данные и активные
  токены этим code fix не удалялись.
