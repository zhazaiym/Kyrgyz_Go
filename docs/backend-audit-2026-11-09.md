# Проверка бэкенда Kyrgyz_Go — 9 ноября 2026

Проверена текущая рабочая копия, включая существовавшие до аудита изменения
каталога, авторизации администратора и видео туров. Фронтенд не изменялся.
Рабочие таблицы и пользовательские медиа не использовались и не изменялись.
Публикация, push и изменение истории Git не выполнялись.

## Исправленные ошибки

В `mysite/api/guest_ai.py` исправлены подтверждённые регрессионными тестами ошибки:

- `2.0` принималось как целое число вопреки контракту context. Включена строгая
  проверка типов; невалидный запрос отклоняется до обращения к ИИ.
- В составном ответе терялись строковые блоки. Используется общая серверная
  функция извлечения текста без преобразования метаданных в строку.
- Сетевой таймаут SDK выдавался как общий 503. Теперь таймауты возвращают 504,
  квота провайдера — 429 с Retry-After, остальные ошибки — безопасный 503.
- Заблокированные и обрезанные ответы с finish_reason SAFETY/MAX_TOKENS
  выдавались как успешные. Теперь принимаются только завершённые текстовые ответы.
- Ошибка PostgreSQL при проверке квоты выходила необработанным исключением.
  Теперь возвращается стандартный безопасный ответ 503.

Создание клиента перенесено в рабочий поток. Проверены отмена ожидания по
дедлайну и освобождение общей квоты параллельных вызовов после отмены.
Unit-тесты по умолчанию подменяют провайдер и не обращаются к реальному ИИ.

Гостевой доступ `/api/ask-ai` сохранён. Существующие HTTP/WS-чаты требуют входа;
проверки чужой сессии и защищённых операций не ослаблялись.

## Изменённые в рамках аудита файлы

- `mysite/api/guest_ai.py` — исправления гостевой консультации.
- `main.py` — порядок импорта гостевого роутера для штатного форматирования.
- `tests/unit/test_guest_ai.py` — расширение с 6 до 27 offline-тестов.
- `tests/test_guest_ai_integration.py` — 3 новых теста с PostgreSQL и настоящим
  приложением: гостевой лимит, общий лимит, граница авторизации и OpenAPI.
- `scripts/backend_smoke.py` — воспроизводимая проверка Uvicorn по TCP/HTTP
  на временной базе; один реальный вызов включается только через `--live-ai`.
- `docs/guest-ai.md` — актуальные типы, ошибки, ключи и запуск smoke.
- Этот отчёт.

Другие изменения, уже присутствовавшие в рабочей папке, сохранены.
`examples/guest-ai.html` в рамках этого аудита не изменялся.

## Среда и безопасность данных

Python 3.12.10, локальная PostgreSQL 17. Docker CLI установлен, но движок Docker
не запущен. Вместо Docker использована доступная локальная PostgreSQL.
В `TEST_DATABASE_URL` передавалось подключение к служебной базе postgres;
`tests.postgres_support.temporary_database` создавал отдельные случайные базы
`test_kyrgyzgo_*` и удалял только их. Рабочая база из DATABASE_URL не мигрировалась.
SQLite не использовалась.

Для полного прогона задан отдельный уникальный `--basetemp` и временный
`FFPROBE_BINARY`: ffprobe 9.0.2 извлечён из FFmpeg в системную временную папку.
PATH и глобальная установка программ не менялись. Dockerfile и CI уже
предусматривали установку FFmpeg. Для обычного запуска вне Docker ffprobe
по-прежнему нужно иметь в PATH или указать через FFPROBE_BINARY.

## Границы проверки

- Docker-образ и Compose-сервисы не запускались: движок Docker недоступен.
  Проверка рендеринга конфигурации Compose входит в прошедший набор тестов.
- Рабочая БД, опубликованный сервер, production HTTPS/reverse proxy, внешнее
  хранилище медиа и фактическая доставка SMTP не проверялись.
- Проверка секретов относится к текущим файлам и логам выполненного smoke,
  а не ко всей истории Git, внешним журналам или стороннему фронтенду.
- Результат одного реального ответа не подтверждает качество произвольных
  диалогов или всех Gemini-сценариев; 16 платных opt-in тестов остались выключены.
- Фронтенд не проверялся и не изменялся; восстановление localStorage на
  опубликованном сайте относится к работе его разработчика.

Блокирующих ошибок кода при запуске на подготовленной отдельной PostgreSQL
не обнаружено. Для запуска с рабочей базой необходимо отдельно проверить её
доступность и применённые ревизии: в этом аудите она намеренно не затрагивалась.
