## Валидация данных: открытые файлы database

### `storage_validation.py`, `input_validation.py`, `schema.py`

`StorageInput` связывает имя входной Pydantic-схемы с ORM-моделью из `mysite.database.models` и вызывает общую функцию `validate_storage_values`. В `models.py` та же функция подключена к событиям `before_insert` и `before_update` для моделей, определённых в этом модуле. Это распространяет проверки на ORM-записи, в том числе из SQLAdmin; прямой SQL и модели из других модулей этим обработчиком не покрываются.

Проверяются явно переданные/изменённые столбцы:

- Для обязательных столбцов запрещён явный `null`; для обязательных строк — пустой текст и пробелы. Длина строки ограничена длиной ORM-столбца, если она задана.
- Целые значения должны быть целыми и помещаться в диапазон PostgreSQL Integer: от −2 147 483 648 до 2 147 483 647.
- Числа `Numeric` должны быть конечными, помещаться в `precision/scale` столбца и не иметь лишних десятичных знаков. Например, цена с тремя знаками после запятой при масштабе 2 отклоняется.
- Внешние ключи `*_id`, дни, минуты, количество участников, мест и пассажиров должны быть положительными. Цена, ночи, часы, расстояние и порядок не могут быть отрицательными.
- Звёзды отеля: 1–5; широта: −90–90; долгота: −180–180.
- Если меняется граница группы, `min_people` не может превышать `max_people`; ORM-проверка учитывает сохранённую вторую границу при частичном обновлении.
- Для `image`, `main_image`, `qr_code` допускается пустая схема URL, `http` или `https`; другие схемы отклоняются. Это проверка схемы, а не доступности адреса.

При ошибке входной схемы API возвращает 422. Примеры граничных случаев находятся в `tests/test_storage_boundaries.py`; это указание на покрытие в исходниках, а не результат нового запуска тестов.

### `booking_validation.py`

`optional_email` используется при проверке контактов чата, регистрации, входа и данных хранения. `None` и строка из пробелов дают `None`; непустой адрес обрезается по краям, проверяется через `email_validator`, нормализуется и приводится к нижнему регистру. Ограничение входа — 254 символа, проверка существования почтового домена отключена (`check_deliverability=False`). Обязательность email определяется вызывающим кодом.

### `catalogue_rules.py`

`is_demo_name` распознаёт названия с префиксом `ТЕСТ:` или `TEST:` без учёта регистра. Правило используется при выборе услуг и формировании снимка услуг заявки. Неактивные, отсутствующие и демонстрационные услуги нельзя принять как действительный выбор. Функция проверяет начало строки; ведущие пробелы она не удаляет.

### `selection_models.py`

`TravelSelection` хранит клиента, необязательные ID тура/отеля/транспорта, связь с чат-сессией, статус (по умолчанию `draft`) и время создания. Внешние ключи связывают запись с соответствующими таблицами. Ограничение `uq_travel_selections_session_id` запрещает нескольким выборам ссылаться на одну непустую сессию; несвязанные черновики могут иметь `session_id=None`.

Требование выбрать хотя бы одну активную настоящую услугу реализовано в `mysite/api/travel_selection.py`, а не отдельным ограничением этой модели. Проверка принадлежности выбора клиенту выполняется в API. Контракт маршрутов и статусов приведён в [API](../API.md).

## Незакоммиченные изменения ИИ

На момент проверки Git показывает изменения в `mysite/chain/prompts.py`, `tests/test_agent_budget.py` и существующем отчёте `ai-review-followup.md`.

| Промпт | Размер в HEAD | Размер в рабочем дереве |
| --- | --- | --- |
| `SYSTEM_PROMPT` | 59 438 символов, 1143 строки | 5980 символов, 38 строк |
| `EXTRACT_PROMPT` | 21 875 символов, 471 строка | 3919 символов, 23 строки |

Сокращены оба промпта. Текущие инструкции сохраняют консультацию на языке клиента, опору на факты read-only инструментов, различение пустой выдачи и ошибки, запрет выдумывать валюту/характеристики и необходимость серверного подтверждения перед отправкой заявки. Извлекатель описывает явные изменения полей, сохранение независимых пожеланий, `clear_fields` и отдельное намерение оформить заявку. Наличие этих правил в тексте не гарантирует их выполнения моделью.

SHA-256 текущих строк промптов (UTF-8, вычислены без импорта приложения):

```text
SYSTEM_PROMPT  10740a3ec672c5e47417917b3dbfd1c9db3c71d61effabc3a0c51ece3ed3bd5d
EXTRACT_PROMPT 6f54550bfc4e38b41ed7478038db614f865a076db9f37ea41c0f52d483d795ab
```

Локальный diff тестов добавляет проверки правил компактных промптов, сохранения состояния при исправлениях/ошибках извлечения и набор синтетических ответов каталога. Сетевые сценарии проверяют пустую выдачу, ошибку инструмента, внедрённую инструкцию и сравнение с неизвестными характеристиками; каждый повторяется три раза и требует явного `RUN_LIVE_GEMINI_EVAL=1`. Условия запуска и прежние результаты находятся в [отчёте ИИ](ai-review-followup.md). При этой документальной сверке сетевые вызовы не выполнялись.
