# Загрузить изменения на сервер одной командой

GitHub не нужен. Команда отправляет текущие сохранённые файлы проекта, включая изменения без commit.

## Запуск

Откройте PowerShell в папке `C:\Users\user\Kyrgyz_Go` и выполните:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\deploy.ps1
```

Сначала выполняются локальные тесты. При их ошибке загрузка не начинается. Затем передаются исходники, сервер делает резервную копию базы и конфигурации, собирает образ и перезапускает только backend. Успех обозначается сообщением `DEPLOYMENT SUCCEEDED`.

Приложение доступно по адресу `https://13.53.40.37`. Пока идёт команда, не закрывайте терминал.

## Проверить доступ без обновления

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\deploy.ps1 -Check
```

Этот режим проверяет упаковку файлов, SSH, наличие серверного deploy-скрипта и здоровый backend. Он не загружает архив на сервер, не применяет миграции и не перезапускает приложение. Успех: `CHECK PASSED`. Проверка сама по себе не гарантирует, что будущая сборка пройдёт: место на диске и зависимости повторно проверяются сервером при настоящем обновлении.

## Ключ и Python

По умолчанию используется личный ключ `C:\Users\user\.ssh\kyrgyzgo_ec2_deploy`. Он не передаётся на сервер или в архив. GitHub Actions Secrets для этой команды не нужны.

Для другого личного ключа:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\deploy.ps1 -KeyPath "$env:USERPROFILE\.ssh\my_server_key"
```

Для Python из подготовленного окружения добавьте `-PythonExecutable "C:\path\to\python.exe"`. Нужен Python 3.12 или новее, зависимости проекта и тестовые пакеты:

```powershell
python -m pip install -r requirements.txt pytest httpx websockets
```

Флаг `-SkipTests` пропускает только локальные тесты. Используйте его осознанно, если эту самую версию уже проверили; проверки и резервная копия на сервере остаются обязательными.

`ExecutionPolicy Bypass` действует только для этого запуска PowerShell и не меняет общую политику компьютера.

## Что отправляется

- Только `main.py`, `create_admin.py`, `seed_demo.py`, `requirements.txt`, `Dockerfile`, `.dockerignore`, `alembic.ini` и каталоги `mysite`, `alembic`, `scripts`.
- Локальные `.env`, ключи, SQLite-базы, кеши, документация, Git и виртуальные окружения не отправляются. Символические ссылки в исходниках запрещены.
- Файлы берутся с диска, поэтому сначала сохраните изменения в редакторе. Изменения в серверных Compose, Caddy и `.env` этой командой не устанавливаются.
- Ручной релиз идентифицируется первыми 40 символами SHA-256 архива; это идентификатор снимка, не Git commit. Он записывается в серверный `deployment-state.json` как `revision`.

## Безопасность и ограничения

- Проверяется заранее доверенный SSH-ключ сервера. При его смене команда остановится: не отключайте проверку, сначала выясните причину.
- Используется уже установленный доверенный `/usr/local/lib/kyrgyzgo/ci_deploy.py`. Скрипт с компьютера не подменяет эту серверную точку входа.
- Если зависимости и Dockerfile не менялись, сохраняется проверенный серверный runtime. Для полной сборки с изменёнными зависимостями нужно минимум 2 GiB свободного места. При свободном месте менее 256 MiB запрещено любое обновление.
- При ошибке сборки прежний backend продолжает работать. При ошибке запуска выполняется откат образа. Применённые миграции автоматически не откатываются; делайте их обратно совместимыми.
- Резервные копии находятся в `/home/ubuntu/kyrgyzgo-backups/ci-*`, исходники — `/home/ubuntu/releases/ci-*`. Автоматического удаления копий или Docker volumes нет.
- Команде выдаются отдельные личные SSH-ключи с обычным серверным доступом. Не пересылайте общий приватный ключ. Ограниченный ключ GitHub Actions не подходит для этой команды проверки.
- Перед обновлением согласуйте изменения с командой. Блокировка предотвращает одновременный перезапуск, но не защищает от последующей загрузки устаревшей версии коллегой. Будущий включённый GitHub Actions также может заменить ручной релиз кодом из `main`.
