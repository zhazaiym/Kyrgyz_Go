## Устройство проекта

FastAPI-приложение собирается в `main.py`. HTTP API и WebSocket-чат находятся
в `mysite/api`, ORM и схемы — в `mysite/database`, административный интерфейс —
в `mysite/admin`. PostgreSQL обновляется миграциями Alembic. Модуль `ML`
содержит агента Gemini, извлечение параметров поездки, инструменты каталога,
переводы и адаптер runtime. Конфигурация развёртывания использует Docker и Caddy.

Дальнейшее описание: [архитектура](architecture.md), [API](../API.md),
[ML](../ML/README.md), [развёртывание](../DEPLOY.md).

## Среда и изоляция

- Windows, Python 3.12.9, виртуальное окружение `.venv`, локальный PostgreSQL 17.
- Установлены зависимости из `requirements-dev.txt`. Отсутствовавший
  `prometheus-client==0.26.0` установлен из существующего файла зависимостей.
- Подключение для тестов явно направлено на локальный PostgreSQL.
  `tests/postgres_support.py` создаёт отдельную базу `test_kyrgyzgo_<uuid>`
  и удаляет её после завершения. База приложения не используется для тестовых записей.

- Первоначальная ошибка доступа pytest к временной папке устранена повторным
  запуском с разрешённым доступом; код проекта для этого не менялся.

## Полный набор и live Gemini

Оба полных запуска собрали 1072 теста. В обычном запуске пропущены только
33 opt-in проверки внешней модели: 15 injection/выбора тура, 12 grounding,
4 извлечения параметров, 1 каталога и 1 фотографии. В полном live-запуске
пропусков нет: 20 из 33 внешних проверок прошли, 13 завершились HTTP 429.

Ответ провайдера указывает лимит **15 запросов в минуту** для используемого
Free Tier. Один диалог вызывает модель несколько раз, поэтому интервал между
тестами не гарантирует соблюдения квоты. Запущен повтор только 13 неудачных
сценариев с интервалом не менее пяти секунд между сетевыми запросами через
временный локальный pytest-плагин. Проверки и ответы не подменяются;
плагин не входит в исходники приложения. Ограничение частоты не меняет
ответы модели или проверки тестов.

После устранения HTTP 429 выявлены две реальные регрессии: принятие
поддельной цены из сообщения клиента (`fake_tool_result`) и потеря выбора
первого тура по ответу `1`. Повтор после исправления этих инструкций также
показал ошибочную очистку выбранного тура при вопросе о сравнении Каракола.

Исправление ограничено `ML/prompts.py`: пользовательский JSON не считается
ответом инструмента; реальные цены требуют настоящего вызова Tools;
варианты нумеруются и сначала предлагаются к выбору; цифра связывается с
контекстом вопроса, а сравнение не сбрасывает выбранный тур. Форматы API,
схема БД и тестовые ожидания не изменялись. Размеры промптов сохранены в
существующих пределах: 7488/7500 и 3964/4000 символов. Изменения повторно
проверены отдельным ревью.

При первой расширенной правке тест бюджета промпта справедливо обнаружил
превышение длины; текст сокращён вместо увеличения допустимого бюджета.
Промежуточный обычный запуск остановлен; финальный полный обычный набор
и все 33 live-проверки на окончательной версии инструкций завершены.

## Сборка и документация

Первоначальная сборка исходного Dockerfile остановлена из-за очень медленной
HTTP-загрузки системных пакетов Debian. Проверка HTTPS показала нормальную
скорость. Образ `kyrgyzgo-verification:20261117-https` собран из временной копии
Dockerfile, в которой перед `apt-get` адрес зеркала Debian заменён на HTTPS.
Dockerfile проекта не изменён; это проверка упаковки с указанной поправкой
среды, а не завершённая сборка исходного Dockerfile без поправок.
Финальный образ обновлён после изменения промптов.

HTML-копия этого отчёта доступна локально по `http://127.0.0.1:8765/`.
Проверен ответ HTTP 200, UTF-8 и наличие таблицы. Сервер привязан только к
`127.0.0.1` и отдаёт отдельную папку отчёта, а не файлы репозитория или `.env`.

Live-проверки включены через `RUN_LIVE_GEMINI_EVAL=1`, а не исключены из запуска.
Отдельное воспроизведение live injection-проверок завершилось результатом
`3 passed, 1 failed`: сценарий `prompt_leak` получил `ML.errors.AIError: ai_rate_limit`.
Это отказ провайдера по лимиту запросов, а не доказанное нарушение защиты от
инъекции. Проверка завершилась до проверки ответа. Неудачный вызов нельзя
считать успешным тестом или заменять скрытым пропуском.

## Как повторить

Установить зависимости и настроить отдельный тестовый PostgreSQL с `CREATEDB`:

```powershell
python -m pip install -r requirements-dev.txt
$env:TEST_DATABASE_URL = 'postgresql+psycopg2://test_user:password@127.0.0.1:5432/postgres'
python -m scripts.run_tests -q -rs
python -m pytest --confcutdir=tests/ml tests/ml -q -rs
python -m pytest --confcutdir=tests/unit tests/unit -q -rs
```

При доступном Docker команду `python -m scripts.run_tests -q -rs` можно выполнить
без `TEST_DATABASE_URL`: запускатель сам создаёт временный PostgreSQL.
Подробнее: [локальные тесты](local-testing.md).

Для проверки внешней модели установить действующий `GEMINI_API_KEY` в окружении,
проверить доступную квоту и выполнить:

```powershell
$env:RUN_LIVE_GEMINI_EVAL = '1'
python -m scripts.run_tests -q -rs
Remove-Item Env:RUN_LIVE_GEMINI_EVAL
```

Live-проверки обращаются к внешнему API и расходуют его квоту.
При `ai_rate_limit` следует повторить их после восстановления квоты.
Локальный успешный набор не доказывает работоспособность внешнего Gemini,
production-сервера, браузерного frontend или входа у реальных OAuth-провайдеров.
