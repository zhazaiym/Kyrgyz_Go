## Что исправлено в AI-агенте

- `ML/price_grounding.py` собирает цены и валюты только из настоящих ответов
  инструментов. Пользовательский JSON не становится доказательством цены.
- Распознаваемые денежные формулировки проверяются перед завершением ответа.
  Числовая часть потокового ответа удерживается до проверки, в том числе
  когда сумма и валюта пришли разными фрагментами.
- При неверной цене выполняется один ограниченный повтор. Если модель снова
  ошибается, ответ составляется из проверенных названий и цен каталога;
  при отсутствии данных агент прямо сообщает, что подтвердить цену не удалось.
- Неизвестная валюта не превращается в USD. Проверены цены с пробелами,
  неразрывными пробелами, суммы без валюты и отдельный повтор бюджета клиента.
- Явный номер показанного тура разрешается по серверному списку `_shown`
  с проверкой активности записи. Такой выбор не требует успешного извлечения
  через Gemini. Ответ на вопрос о числе людей не выбирает тур.
- При выборе готового тура удаляются устаревшие пожелания о направлении
  и длительности. Сам выбор не считается подтверждением заявки.
- Название услуги должно сохраняться дословно из каталога.

Новые регрессионные тесты сначала воспроизвели ошибки, затем прошли после
исправления. Существующие ожидания live-тестов не ослаблялись.

## Устройство проекта

`main.py` собирает FastAPI-приложение. `mysite/api` содержит HTTP API,
WebSocket-чат и авторизацию; `mysite/database` — ORM и схемы;
`mysite/admin` — административный интерфейс. PostgreSQL обновляется Alembic.
`ML` содержит агента Gemini, извлечение параметров поездки, инструменты
каталога, проверку цен и адаптер runtime. Frontend сайта отсутствует
в этом репозитории.

Подробнее: [архитектура](architecture.md), [API](../API.md),
[ML](../ML/README.md), [развёртывание](../DEPLOY.md),
[локальные тесты](local-testing.md).

## Среда и ограничения проверки

Использованы Windows, Python 3.12.9, `.venv` и локальный PostgreSQL 17.
Тесты создают случайную базу `test_kyrgyzgo_<uuid>` и удаляют только её.
База приложения для тестовых записей не используется. Секреты передаются
через окружение и не включаются в Git или этот отчёт.

Live-проверки включались через `RUN_LIVE_GEMINI_EVAL=1`. Временный pytest-плагин
выдерживал не менее пяти секунд между настоящими сетевыми запросами, чтобы
соблюдать обнаруженную квоту 15 запросов в минуту. Он не подменяет ответы
модели и не меняет проверки. Сам код агента не получает искусственную задержку.

Для контейнерной проверки использована временная копия Dockerfile с HTTPS
вместо медленного HTTP-зеркала Debian. Dockerfile проекта не изменён.
Контейнер собран после слияния main; последние правки названий и пунктуации
проверены отдельно, окончательную упаковку повторяет GitHub CI.

XML-результаты находятся локально в `.ml-test-tmp/main-offline-results.xml`,
`.ml-test-tmp/final-live-results.xml` и `.ml-test-tmp/main-grounding-results.xml`.
Эта папка исключена из Git.

## Как повторить

```powershell
python -m pip install -r requirements-dev.txt
$env:TEST_DATABASE_URL = 'postgresql+psycopg2://test_user:password@127.0.0.1:5432/postgres'
python -m scripts.run_tests -q -rs
python -m pytest --confcutdir=tests/ml tests/ml -q -rs
python -m pytest --confcutdir=tests/unit tests/unit -q
python -m ruff check .
python -m scripts.format_code --check
```

Без `TEST_DATABASE_URL` запускатель использует временный PostgreSQL в Docker.
Для live-проверок нужен действующий `GEMINI_API_KEY`, квота и переменная:

```powershell
$env:RUN_LIVE_GEMINI_EVAL = '1'
python -m scripts.run_tests -q -rs
Remove-Item Env:RUN_LIVE_GEMINI_EVAL
```

Live-запуск расходует квоту внешнего API. При 429 или 503 результат необходимо
разобрать и повторить после восстановления сервиса, а не скрывать пропуском.
