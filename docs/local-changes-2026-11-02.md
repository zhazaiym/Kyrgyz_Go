# Локальные изменения и состояние проекта — 2 ноября 2026

Это снимок локального рабочего дерева, зафиксированный 2 ноября 2026 года. Он
не является подтверждением текущего состояния кода или production. В нём есть изменения,
которые были в проекте до последнего запроса; ниже они отделены от исправлений
чата и ИИ, сделанных при последней проверке. Production-сервер в рамках этой
работы не изменялся.

## Последние исправления чата и ИИ

- В `mysite/admin/realtime.py` удалён импорт `WebSocketDisconnected`: установленная
  версия Starlette предоставляет `WebSocketDisconnect`, а ошибочный импорт
  останавливал загрузку всего приложения до регистрации маршрутов чата.
- В `.env.example` и инструкции `DEPLOY.md` production-origin
  `https://kyrgyzgo-admin.vercel.app` добавлен в `CHAT_ALLOWED_ORIGINS`. HTTP CORS
  и WebSocket проверяют origins отдельно.
- В `ML/provider.py` убран параметр `temperature` у translation-клиента. Модель
  его игнорировала и выдавала предупреждение.
- В `tests/test_deployment_files.py` добавлена проверка production-origin для
  WebSocket; в `tests/test_ai_config.py` — проверка, что translation-клиент не
  передаёт игнорируемый параметр.
- В `tests/test_agent_budget.py` live-eval использует модель из `GEMINI_MODEL`,
  а не отсутствующий атрибут `agent.model_name`.

## Остальные изменения в локальном рабочем дереве

Эти пункты зафиксированы для полного обзора текущего состояния и не все относятся
к последнему исправлению чата.

### Админка и вход

- `mysite/admin/setup.py`: cookie админской сессии настроена без таймера
  `max_age`; cookie Secure в production, SameSite Strict; явный logout очищает
  сессию.
- `mysite/api/admin_access.py`: сетевое ограничение по IP отключено; проверка
  учётной записи остаётся отдельным уровнем доступа.
- `.env.example`, `DEPLOY.md`, тесты и `docs/reviewer-context.md` обновлены под
  текущую политику доступа к админке и лимит попыток входа.
- `mysite/admin/realtime.py`, `mysite/admin/templates/sqladmin/base.html` и
  `tests/test_admin_realtime.py`: добавлены уведомления админки о новых заявках.
  `mysite/api/chat_service.py` публикует событие после успешной фиксации заявки.
- `tests/test_admin_session_lifetime.py`: покрывает сохранение сессии до явного
  logout.

### Контент сайта

- `mysite/api/home_content.py` и регистрация маршрута в `main.py` добавляют
  endpoint текста главной страницы; `mysite/about_content.py` содержит контент
  страницы «О нас».
- `mysite/faq_content.py` содержит записи FAQ; миграции `0018`, `0019` и `0020`
  заменяют, очищают и заново заполняют каталог FAQ.
- `scripts/replace_about_content.py` заменяет контент страницы About с созданием
  резервной копии; добавлены спецификация и план в `docs/superpowers/`.

### Переводы

- `ML/translation.py`: добавлена ограниченная попытка восстановить ответ Gemini,
  если между языковыми объектами JSON продублирована закрывающая скобка.
- `DEPLOY.md` содержит описание обновлённого контента и процесса замены About.

### Развёртывание

- `scripts/ci_deploy.py`: конфигурация production Compose использует сеть `proxy`,
  фиксированный адрес API, отдельные production env-файлы; выбор контейнера
  PostgreSQL выполняется по Compose labels. Валидация допускает явное значение
  `ADMIN_ALLOWED_IPS=0.0.0.0/0,::/0`.
- `scripts/manual_deploy.py` проверяет health API-контейнера через Compose project
  и service, а не через старое имя контейнера.
- Добавлены/обновлены соответствующие тесты в `tests/test_ci_deploy.py`,
  `tests/test_app_config.py` и `tests/test_deployment_files.py`.

## Что ещё не подтверждено для production

- Живой вызов Gemini с локальной машины завершился `ConnectError`; сетевой доступ
  до провайдера из этой среды не подтверждён. Проверки тестами не заменяют этот
  внешний вызов.
- Все 12 live-eval сценариев были запущены с `RUN_LIVE_GEMINI_EVAL=1`, но каждый
  завершился сетевым `ConnectError` до ответа модели. После устранения ошибки в
  метаданных теста сценарии доходят до вызова провайдера; для оценки качества
  ответов нужен сетевой доступ к Gemini.
- Локальный Docker Engine недоступен, поэтому production-образ локально не
  собирался. Проверены Compose-конфигурация и упаковочные тесты.
- По последней проверке production всё ещё использует старый backend без пакета
  `ML` и AI/chat-маршрутов. Изменения в этот сервер не отправлялись.
- Production DB была на `20261028_0016`; чату требуется миграция `20261029_0017`.
  Локальная вершина `20261030_0020` включает также FAQ-миграции `0018–0020`; их
  нельзя запускать при chat-only обновлении без отдельной проверки, поскольку
  они меняют содержимое FAQ.
- Последняя проверка production deploy обнаружила устаревший серверный allowlist,
  не принимающий `ML`, и недостаток места для полной сборки: требовалось 2 GiB,
  было около 144 MiB. Серверные файлы и диск не менялись.
- `.deploy-debug.tar.gz` и вложенное изменение `.chat-deploy/github-prompt-upload`
  присутствовали в рабочем дереве; они не проверялись как исходники приложения и
  не включены в список функциональных изменений выше.
