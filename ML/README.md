# Kerben Travel AI: Gemini / ML

`agent.py` выполняет консультацию и извлечение полей; `prompts.py` хранит компактные инструкции. `schemas.py` задаёт результат извлечения, `context.py` ограничивает историю. `tools.py` содержит только чтение каталога. `translation.py` вызывает модель для переводов; задачи и сохранение переводов остаются в `mysite/translations`.

`provider.py` лениво создаёт клиентов. Импорт пакета не требует ключа Gemini или подключения PostgreSQL. Для реального AI-ответа задайте `GEMINI_API_KEY`; при чтении каталога также нужна доступная PostgreSQL. Если ключ отсутствует или недействителен, WebSocket может принять подключение и отправить приветствие, но сообщение чату завершится `ai_unavailable`. Это один backend-процесс с внешним Gemini API, отдельный контейнер AI не запускается. `errors.py` преобразует ошибки SDK в безопасные категории без публикации текста провайдера. Бронирование и проверка прав находятся в `mysite/api`.

Старые импорты `mysite.chain.*` и `mysite.translations.translator` временно совместимы с новым пакетом и используют те же объекты модулей. Новые потребители должны импортировать из `ML`.

Лимиты: 150 секунд на полный ответ по умолчанию (`CHAT_RESPONSE_TIMEOUT`, допустимо 10–170), до пяти раундов модели, до восьми tool calls суммарно, 15 секунд на один инструмент, 16 000 символов на результат инструмента, 65 536 символов текста ответа. Большой результат заменяется сообщением о неполной выдаче. Допустимые ID для извлечения ограничены первыми 256 активными турами; текущий и новый явно выбранный ID вне списка проверяются отдельным точным запросом. Ошибка БД не считается пустым каталогом.

В каждом раунде до объединения фрагментов проверяется весь сериализованный поток, включая нетекстовые блоки, метаданные и аргументы tools: максимум 1 MiB и 8192 фрагмента. Превышение отклоняется до вызова инструментов и отправки ответа клиенту.

Неполный ответ из-за MAX_TOKENS допускает один компактный повтор в пределах общего deadline. Блокировка провайдера и некорректный вызов инструмента не публикуются как успешный ответ. Ошибка извлечения сохраняет исходные данные и не создаёт намерение бронировать.

Проверки без БД, ключа и сетевых запросов:

```powershell
.venv/Scripts/python.exe -B -m pytest --confcutdir=tests/ml tests/ml -q
```

Интеграционные проверки используют `TEST_DATABASE_URL` с правом CREATEDB: тестовая фикстура создаёт и удаляет только временные `test_kyrgyzgo_*` базы. Live-eval Gemini включаются отдельно и по умолчанию пропущены.

При развёртывании нужен весь каталог `ML`. Dockerfile и локальный архиватор обновлены. Для новой связи ответа с репликой требуется миграция `20261029_0017`; старые сообщения сохраняются с пустой связью. Доверенный серверный deploy-скрипт с прежним allowlist не примет архив с `ML`: его обновляет администратор отдельно по [инструкции](../docs/manual-deployment.md). Само изменение исходников на сервере ничего не развёртывает.


## Reliability notes

FAQ lookup returns only rows with an actual text match; an empty result means the agent must say that the policy was not found. Tour destination search includes the linked country. AI provider metrics use fixed operation labels and never record user text.

Поиск нормализует пробелы и дефисы, а также варианты `Issyk-Kul`, `Ысык-Көл` и `Иссык Куль`. `duration_days` означает точную длительность; `min_duration_days` и `max_duration_days` задают диапазон без автоматического ослабления условий клиента. `%`, `_` и `\` остаются буквальными символами поиска. Модели передаётся только один инструмент каталога — `search_tours`; без фильтров он возвращает краткий каталог. `list_active_tours` сохранён для совместимости Python-импортов, но его схема в запросы Gemini не включается.

На каждый вызов `respond` записывается одна строка INFO: общий исход, полная длительность и список длительностей/исходов извлечения, генерации и инструментов. Строка пишется в `finally`, включая ошибки и таймауты; пользовательский текст и значения ключей в неё не попадают. Метрики этапов сохраняются отдельно. Независимые одновременные ответы используют отдельные контексты замеров.

Извлечение относительных дат и проверка даты заявки используют календарную дату Бишкека (UTC+6). После отказа от сводки вопрос без изменения данных получает ответ консультанта; новая сводка появляется при исправлении данных или новом намерении оформить заявку. Созданная из чата заявка привязана к клиенту и доступна ему в `/travel-requests/me/`.

Полный прогон с реальным Gemini требует явного `RUN_LIVE_GEMINI_EVAL=1` и действующего ключа в окружении до загрузки тестовой фикстуры. Для загрузки локального `.env`, запуска изолированной БД и сохранения отчёта:

```powershell
$env:RUN_LIVE_GEMINI_EVAL='1'
python -c "from dotenv import load_dotenv; load_dotenv(); from scripts.run_tests import run_tests; raise SystemExit(run_tests(['-q', '-o', 'junit_family=xunit1', '--junitxml=live-test-results.xml']))"
```

Проверки с живой моделью разделяют один цикл `asyncio`, чтобы клиент SDK не переиспользовал соединения из закрытого цикла. Тесты извлечения отдельно проверяют смену направления, сравнение туров и дату «завтра».
