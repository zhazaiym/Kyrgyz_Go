# Gemini / ML

`agent.py` выполняет консультацию и извлечение полей; `prompts.py` хранит компактные инструкции. `schemas.py` задаёт результат извлечения, `context.py` ограничивает историю. `tools.py` содержит только чтение каталога. `translation.py` вызывает модель для переводов; задачи и сохранение переводов остаются в `mysite/translations`.

`provider.py` лениво создаёт клиентов. Импорт пакета не требует ключа Gemini или подключения PostgreSQL. Для реального запроса нужны настройки окружения и, при чтении каталога, доступная БД. `errors.py` преобразует ошибки SDK в безопасные категории без публикации текста провайдера. Бронирование и проверка прав находятся в `mysite/api`.

Старые импорты `mysite.chain.*` и `mysite.translations.translator` временно совместимы с новым пакетом и используют те же объекты модулей. Новые потребители должны импортировать из `ML`.

Лимиты: 150 секунд на полный ответ по умолчанию (`CHAT_RESPONSE_TIMEOUT`, допустимо 10–170), до пяти раундов модели, до восьми tool calls суммарно, 15 секунд на один инструмент, 16 000 символов на результат инструмента, 65 536 символов текста ответа. Большой результат заменяется сообщением о неполной выдаче. Допустимые ID для извлечения ограничены первыми 256 активными турами; текущий и новый явно выбранный ID вне списка проверяются отдельным точным запросом. Ошибка БД не считается пустым каталогом.

В каждом раунде до объединения фрагментов проверяется весь сериализованный поток, включая нетекстовые блоки, метаданные и аргументы tools: максимум 1 MiB и 8192 фрагмента. Превышение отклоняется до вызова инструментов и отправки ответа клиенту.

Неполный ответ из-за MAX_TOKENS допускает один компактный повтор в пределах общего deadline. Блокировка провайдера и некорректный вызов инструмента не публикуются как успешный ответ. Ошибка извлечения сохраняет исходные данные и не создаёт намерение бронировать.

Проверки без БД, ключа и сетевых запросов:

```powershell
.venv/Scripts/python.exe -B -m pytest --confcutdir=tests/ml tests/ml -q
```

Интеграционные проверки используют `TEST_DATABASE_URL` с правом CREATEDB: тестовая фикстура создаёт и удаляет только временные `test_kyrgyzgo_*` базы. Live-eval Gemini включаются отдельно и по умолчанию пропущены.

При развёртывании нужен весь каталог `ML`. Dockerfile и локальный архиватор обновлены. Для новой связи ответа с репликой требуется миграция `20261029_0017`; старые сообщения сохраняются с пустой связью. Доверенный серверный deploy-скрипт с прежним allowlist не примет архив с `ML`: его обновляет администратор отдельно по [инструкции](../docs/manual-deployment.md). Само изменение исходников на сервере ничего не развёртывает.
